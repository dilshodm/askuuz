# CHANGELOG

Все значительные изменения в этом проекте будут задокументированы в этом файле.

## [Unreleased]

### ✨ Добавлено

- **Газоснабжение отдельной услугой**: газ больше не требует настроенной
  управляющей компании. Эндпоинт `/gaz` использует только вход в кабинет
  kommunal.uz, поэтому газ можно добавить как самостоятельную услугу со своим
  устройством и сенсорами. Прежний способ (газ как опция УК) продолжает
  работать — один и тот же лицевой счёт нельзя добавить обоими способами.

### 🐛 Исправлено

- **Авторизация**: любая ошибка входа — включая таймаут и разрыв соединения —
  сообщалась как `ConfigEntryAuthFailed`, поэтому кратковременный сбой сети
  переводил рабочую запись в состояние «требуется повторная авторизация».
  Теперь временные ошибки транспорта отделены от отказа сервиса
  (`TransientApiError`, `is_transient()`).
- **Повторная авторизация**: в config flow не было шага `reauth`, поэтому
  восстановить запись после смены пароля можно было только удалив и добавив
  интеграцию заново. Добавлены шаг `reauth_confirm` и переводы к нему.
- **Настройка**: при недоступности сервиса форма показывала «неверный логин или
  пароль». Добавлена отдельная ошибка `cannot_connect`.
- **Платформы**: номер лицевого счёта для устройств и entity брался из данных
  координатора — если первый запрос ничего не вернул, настройка платформы
  падала с `'NoneType' object is not subscriptable`. Теперь он берётся из
  записи конфигурации.
- **Водоснабжение**: обновление данных падало с ошибкой
  `unsupported operand type(s) for +: 'int' and 'NoneType'`, если API uzsuv.uz
  возвращал `null` вместо `0`. Так происходит для любого периода без
  перерасчёта (`corr`), без начисления (`chrg`), без платежа (`psum`),
  без показаний (`om3`) и без сальдо (`sld_sum`). Все числовые поля ответа
  теперь проходят через `as_number()` (общий помощник в `api/base.py`).
- **Управляющая компания и газ**: те же `null` в `balance`, `price`, `my_area`,
  `payment_amount`, `monthly_accrual` и `current_balance` роняли обновление
  (`abs(None)`, умножение и деление на `None`). Нормализация вынесена в
  `api/normalize_management.py` и переведена на `as_number()`.
- **Управляющая компания**: расчёт тарифа за прошлый месяц делил на площадь
  квартиры без проверки — при нулевой площади это `ZeroDivisionError`.
- **Электроэнергия**: лицевой счёт без единого платежа (`lastPayment: null`)
  ронял обновление целиком с сообщением «Failed to parse».
- **ТБО**: строка статистики без ключа `accrual` вызывала `KeyError`, который
  не ловился окружающим `except (TypeError, ValueError)`.

### 🧪 Тесты

- Добавлены тесты газоснабжения: config flow, защита от дубликатов лицевого
  счёта, создание устройства и сенсоров, а также регрессия на связку УК + газ

- Добавлен каталог `tests/` и набор тестов для клиентов водоснабжения,
  электроэнергии, ТБО и управляющей компании (91 тест)
- Добавлены тесты config flow, повторной авторизации, классификации ошибок и
  настройки платформ (требуют `pytest-homeassistant-custom-component`)
- Добавлен `.isort.cfg`: без него `black` и `isort` из CONTRIBUTING.md
  форматировали импорты по-разному и отменяли работу друг друга
- Тесты в CI больше не помечены `continue-on-error`
- Добавлены `pytest.ini` и `requirements-dev.txt` (упоминался в CONTRIBUTING.md,
  но отсутствовал в репозитории)

## [1.0.0] - 2026-01-30

### ✨ Добавлено

- **Основная функциональность**
  - Поддержка 4 сервисов: Электроэнергия, Водоснабжение, ТБО, Управляющая компания
  - Получение информации о балансе, потреблении и начисленной сумме
  - Автоматическое обновление каждые 12 часов

- **Безопасность и валидация**
  - Валидация учётных данных перед сохранением конфигурации
  - Проверка на дубликаты (по сервису, логину и лицевому счёту)
  - Безопасное хранение паролей в Home Assistant

- **Интерфейс пользователя**
  - Кнопка "Обновить данные" для каждого сервиса
  - Три сенсора на каждый сервис (баланс, показатели, начисления)
  - Локализация на 3 языках (Русский, English, O'zbekcha)

- **Автоматизации**
  - Сервис `askuuz.refresh_data` для обновления данных
  - Опциональный параметр `entry_id` для выборочного обновления
  - Возможность обновить все конфигурации одновременно

- **Документация**
  - Полный README.md с примерами использования
  - Документация по установке и настройке
  - Примеры автоматизаций

### 🔧 Технические детали

- Архитектура на основе DataUpdateCoordinator для стабильной работы
- Поддержка воссоздания сущностей при разрыве соединения
- Кеширование последних успешных данных
- Обработка ошибок 401/403 с автоматическим переподключением

### 📝 Примечания

- Первый релиз компонента
- Все основные функции реализованы и протестированы
- Готов к использованию в production
